Build & prompt log

ENSG AI Class · Assignment 3. This site was vibe-engineered: scoped, chain-of-thought prompts, each reviewed and refactored before the next. Every prompt is below; the same log ships as PROMPTS.md, and condensed banners sit above each section in the page source.

Vibe coding vs. vibe engineering

Vibe coding accepts the first output. Vibe engineering runs the AI like a teammate under review — one scoped, chain-of-thought prompt per section, tested against acceptance criteria, then refactored. Here's the whole loop.

P0Theme, name, crest & tokens ›

Let's think step by step before any code. (1) Theme = an Old Students' Association; give it a credible name, founding year and motto. (2) A crest is the identity anchor for a college body — design a heraldic shield (book of knowledge + rising sun) in the palette. (3) Palette + type: heritage green/gold on ivory is grounded in the subject (a school crest), not the generic AI default — pick a display SERIF with real character (Fraunces), a civic body face (Libre Franklin), and a mono for the log. (4) Decide the page set and menu structure. Only after this plan do we write markup.

Accepted: Name = Crestfield College OSA · crest drawn · forest/gold/cream + Fraunces/Libre Franklin/JetBrains Mono · 8 pages, 3 dropdowns.

P1Information architecture ›

Think about the visitor before the pixels. Which pages does an alumnus actually need, and how do they group? Draft the sitemap: Home; About (story/EXCO/constitution); Membership (why/register/dues); Community (events/news/projects); Contact — plus a footer-only build log. Group the middle three under dropdowns so the top bar stays calm.

Accepted: 8 pages, 3 dropdown groups, 1 CTA (Join/Donate). Community groups events+news+projects.

P2Sticky menu bar + dropdowns ›

Build only the header. Sticky, forest with a gold underline. Left: crest + wordmark. Right: nav where About/Membership/Community are dropdowns linking to real pages and anchors. Requirements: open on hover AND keyboard (focus-within), highlight the current page in gold, and provide a mobile hamburger that expands the same links (generate desktop + mobile from ONE model so they can't drift).

Accepted: Sticky ✓ · dropdowns keyboard-openable ✓ · current page gold ✓ · mobile menu from same data ✓.

P3Home / hero ›

One job for this page: make an alumnus feel belonging and click Join. Step through it: a forest hero with the crest, a warm 'Welcome home, Crestfielder' headline, motto and two CTAs; then three credibility numbers; then a 3-pillar 'what we do'; then the featured reunion beside three news teasers; end on a membership band. Dignified, not corporate.

Accepted: Hero + stats + pillars + event/news + CTA. Copy stays warm and specific.

P4About (story · EXCO · constitution) ›

Trust before detail. Lead with a short history and mission/vision, then a real timeline (history is a genuine sequence, so ordered markers are earned, not decorative), then the named Executive Council with SET years (a Crestfield signature), then a plain-language constitution summary with a placeholder PDF. Don't fabricate legal text.

Accepted: Mission/vision · 4-milestone timeline · 6 EXCO cards · governance summary. #exco and #constitution anchors.

P5Membership (benefits · register · chapters) ›

Reduce friction. Benefits first (4 cards), then registration as THREE steps not a wall, then one lightweight, client-validated form that is honest about having no backend yet, then a dues + chapters list. Every step should lower the effort to say yes.

Accepted: Benefits · 3-step register · validated form · 6-chapter list. Honest 'connect a backend' note.

P6Events, News & Projects ›

Three community pages, one pattern each. Events: one featured homecoming + an upcoming list + a past-reunion gallery. News: a category-tagged card feed, newest first, obituaries handled with care. Projects: impact numbers BEFORE the ask, concrete projects with funding progress bars, then one clear donate CTA. Money follows credibility.

Accepted: Featured+list+gallery · tagged news feed · impact+progress+donate. Placeholders flagged honestly.

P7Contact ›

Make reaching a human effortless: a validated message form on one side, real secretariat details + a map placeholder on the other. Same kind, honest validation as membership.

Accepted: Form + secretariat + map placeholder · client-validated · backend flagged.

P8Sticky footer, JS & QA ›

A big footer can't sit at bottom:0 without covering content, so split it: rich columns in normal flow, THEN a slim sticky bar (copyright + build-log link + back-to-top) as the always-present footer. Add ~30 lines of vanilla JS for the mobile toggle, footer year, and form validation. QA: tag-balance every page, contrast on green/gold, reduced-motion, mobile to 360px.

Accepted: Rich footer + slim sticky bar ✓ · JS minimal & commented ✓ · all pages validated ✓.

Engineering the vibe code

Four edits I did NOT leave to the AI

8 hand-copied pages → one generator

The vibe draft pasted the nav and footer into every file. I moved them into shared partials and generate the pages, so the crest or a menu item changes in one place — no drift across eight files.

div onclick → real dropdown links

First pass used <div onclick> for menu items. Refactored to semantic <a href> so the menu is keyboard-navigable, works without JS, and the dropdowns open on focus-within, not just hover.

Full footer at bottom:0 → slim sticky bar

A sticky full footer covered page content on short screens. Split into a normal-flow footer + a thin always-visible bar so the requirement is met without hurting readability.

Silent placeholders → honest flags

The forms and payment/PDF buttons look real; every one is labelled as a demo that needs a backend/gateway, so nothing false ships.

Stack & how to run

Built in VS Code with HTML + Tailwind CSS (Play CDN) + a little vanilla JS. To run fully offline, compile Tailwind with the CLI (as in the nexus-app project) into a local styles.css and swap the CDN line. Add real photos to assets/img/ and they fade into the tiles automatically.
